Key

O que é. Bytes opcionais no record. O particionador padrão do cliente faz Utils.toPositive(murmur2(key)) % numPartitions. Mesma key + mesmo N de partições → mesma coluna → ordem daquela entidade. Sem key, o produtor espalha (sticky partitioner nas versões recentes: uma coluna por um tempo, para batch, não “rodízio justo por mensagem”).

Analogia: o sobrenome na lista. Família Silva na mesma coluna; a história dela fica em ordem.

Na prática. O segundo argumento do send é a key. No lab, pedidoId:

kafka.send("pedidos.criados", pedidoId, evento);
// sem key (lab 1):
kafka.send("pedidos.criados", null, evento);

HTTP equivalente:

curl -X POST "http://localhost:8080/pedidos?pedidoId=99&comKey=true"
curl -X POST "http://localhost:8080/pedidos/lote?comKey=false&n=9"

No lab. PedidoProducer.publicar(..., comKey). Olhe no log partition= e key=.

Key = timestamp ou UUID novo a cada evento destrói ordem por pedido. Sempre a mesma key (ou um cliente gigante) cria partição quente: uma coluna com lag, as outras zeradas.
