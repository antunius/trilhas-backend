Consumidor e consumer group

O que é. O consumidor faz Fetch no líder das partições que o grupo lhe atribuiu, processa, e (em geral) commita offset. group.id é o crachá: o coordenador do grupo trata todos os membros com o mesmo id como um só time. Protocolo: join group → assign partições → heartbeat. Outro group.id = outra marca no mesmo tópico (fan-out). Duas instâncias com o mesmo group.id dividem as partições, não duplicam o recado.

Analogia: um time com o mesmo crachá. Outro time, outro crachá, lê o caderno de novo com a própria marca.

Na prática. Dois listeners no mesmo processo, dois grupos:

@KafkaListener(topics = "pedidos.criados", groupId = "faturamento")
public void faturamento(ConsumerRecord<String, PedidoCriado> rec, Acknowledgment ack) {
    log.info("partition={} offset={} key={}", rec.partition(), rec.offset(), rec.key());
    ack.acknowledge();
}

@KafkaListener(topics = "pedidos.criados", groupId = "analytics")
public void analytics(...) { ... }

concurrency: 3 no YAML = até 3 membros no mesmo grupo — teto = 3 partições.

No lab. PedidoConsumer.java, spring.kafka.consumer.group-id: faturamento e lab.analytics-group: analytics.

Mais consumidores no grupo do que partições = threads sem assignment. Escalar de verdade = mais partições e mais consumidores.
