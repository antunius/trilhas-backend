Schema Registry

O que é. Um serviço HTTP (no lab: porta 8081) que guarda versões de schema por subject (em geral {tópico}-value e {tópico}-key). O producer, com o serializer Confluent, registra o schema se ainda não existe, e manda no wire um magic byte + schema id + payload (não um JSON solto “sem contrato”). O consumer pede o schema daquele id ao Registry e desserializa. Nível de compatibilidade (BACKWARD no Compose): o Registry recusa PUT/POST de schema que quebra quem já lê. BACKWARD = consumidor novo lê dado antigo. FORWARD = consumidor antigo lê dado novo. Campo opcional novo costuma ser BACKWARD-safe. Remover ou renomear campo obrigatório não é.

Analogia: um cartório de contratos. Ninguém muda o formulário sem checar se o outro lado ainda lê.

Na prática. Sobe no Compose. YAML do app:

spring.kafka.producer.value-serializer: io.confluent.kafka.serializers.json.KafkaJsonSchemaSerializer
spring.kafka.consumer.value-deserializer: io.confluent.kafka.serializers.json.KafkaJsonSchemaDeserializer
spring.kafka.producer.properties.schema.registry.url: http://localhost:8081

Depois do primeiro produce:

curl -s http://localhost:8081/subjects
curl -s http://localhost:8081/subjects/pedidos.criados-value/versions/1

Evolução que o cartório recusa (some o campo obrigatório) — comando no README do lab. Passo a passo de compatibilidade: Integração.

No lab. Serviço schema-registry no Compose; record PedidoCriado com eventId, pedidoId, totalCentavos obrigatórios e cupom opcional.

Sem Registry, um produtor muda total para amount e todos os consumers em produção quebram no deserializer. JSON “na mão” no tópico não tem esse travão.
