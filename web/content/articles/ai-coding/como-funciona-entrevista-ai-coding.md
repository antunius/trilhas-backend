## Objetivos de aprendizagem

- [ ] Entender o formato típico desse tipo de entrevista
- [ ] Reconhecer que usar bem a IA é uma habilidade avaliada, não um "atalho" que desqualifica o candidato

## Conteúdo

### O formato típico

Diferente de uma entrevista de código tradicional (resolvida sem ferramentas de IA), aqui o candidato tem acesso a um assistente de IA e é esperado que o use para implementar uma funcionalidade real — não um problema de algoritmo isolado, mas algo mais próximo do trabalho do dia a dia (adicionar uma feature a uma base de código existente, por exemplo).

### O que é avaliado

- **Qualidade do prompt inicial**: você consegue descrever a tarefa de forma clara o suficiente para a IA gerar algo próximo do esperado, sem ambiguidade desnecessária?
- **Revisão crítica**: você aceita o código gerado sem questionar, ou você o examina de forma crítica antes de integrá-lo?
- **Iteração**: quando o resultado inicial não é satisfatório, você consegue refinar o prompt de forma eficaz, em vez de simplesmente pedir "tente de novo"?
- **Comunicação**: você consegue explicar as decisões tomadas ao longo do processo, mesmo quando parte do código foi gerado pela IA?

### Por que usar IA bem é uma habilidade avaliada

Um erro comum é achar que essa entrevista "não testa nada de verdade", já que a IA escreve boa parte do código. Na prática, ela testa uma habilidade cada vez mais relevante no trabalho real: dirigir uma ferramenta poderosa de forma eficaz, mantendo julgamento crítico sobre o resultado — muito diferente de simplesmente aceitar tudo que é gerado sem questionamento.

## Exemplo aplicado

Ao receber a tarefa "adicione um endpoint de busca por nome a essa API", um candidato forte primeiro entende a base de código existente, formula um prompt específico mencionando convenções já usadas no projeto, revisa o código gerado buscando por casos extremos não tratados (ex: busca vazia, caracteres especiais), e só então integra a mudança.

## Erros comuns

- Aceitar o primeiro resultado gerado pela IA sem nenhuma revisão crítica.
- Não conseguir explicar por que uma parte específica do código gerado funciona, quando questionado pelo entrevistador.
